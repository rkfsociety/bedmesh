# План улучшений Windows-версии BedMesh

## Цель

Повысить надёжность Windows-клиента при повреждённых конфигурациях, обрывах
SSH/SFTP, обновлении EXE и обычном запуске проекта из корня репозитория.
Сохранить текущие функции UI, mesh-визуализации и локальной сети.

## Этапы и критерии приёмки

### 1. Единый запуск проверок

- Проблема: тесты используют несовместимые импорты; запуск из корня падает и
  не обнаруживает UI-тесты.
- Место: `win/pyqt6/run_tests.py`, `.github/workflows/build_win_pyqt6.yml`.
- Реализация: добавить штатный runner на `unittest`, который явно собирает
  suites из `core`, `utils` и `ui/components`, сам настраивает пути импортов и
  при необходимости включает Qt offscreen; не добавлять новую обязательную
  зависимость только ради запуска существующих unittest-тестов.
- Проверка: `python win/pyqt6/run_tests.py` из корня запускает все текущие
  тесты; CI выполняет эту команду до PyInstaller.
- Откат: изменения ограничены импортами, конфигурацией тестов и CI; сборочную
  команду PyInstaller не менять без отдельной причины.

### 2. Устойчивый разбор mesh

- Проблема: некорректные JSON-значения в `points` выбрасывают `ValueError`;
  размеры и числовые значения недостаточно строго проверяются.
- Место: `win/pyqt6/core/mesh_parser.py` и `test_parser.py`.
- Реализация: единая валидация размеров, конечности чисел, точного количества
  точек и корректного `probe_count`; добавить негативные fixture-тесты.
- Проверка: повреждённые/неполные данные возвращают предсказуемый результат и
  не показывают пользователю traceback.
- Откат: не менять поддерживаемые JSON/config-форматы и порядок координат.

### 3. Безопасная запись конфигурации

- Проблема: локальный `printer.cfg` перезаписывается напрямую, а SFTP-загрузка
  идёт сразу в конечный путь.
- Место: `win/pyqt6/ui/components/config_editor.py`,
  `win/pyqt6/core/ssh_client.py` и тесты SSH-операций.
- Реализация: локальный temp + `os.replace`; удалённый temp в той же папке,
  SHA-256 до rename, удаление temp при ошибке; существующий backup оставить
  обязательным поведением.
- Проверка: запись не оставляет частичный файл; mismatch не заменяет конечный
  файл; успешная операция сохраняет текущий пользовательский workflow.
- Откат: при ошибке rename сохранить исходный remote-файл и вернуть код
  операции; временные файлы очищать best-effort.

### 4. SSH worker lifecycle и fallback-файл

- Проблема: worker-объекты не удаляются явно; fallback на
  `printer_mutable.cfg` зависит от нескольких basename.
- Место: `config_editor.py`, `app.py` и тесты.
- Реализация: связать worker с `deleteLater`, централизовать завершение потока,
  запускать fallback после SSH-загрузки любого printer-конфига без жёсткого
  списка имён.
- Проверка: повторные SSH-операции не накапливают worker; пользовательский
  путь к `printer.cfg` также ищет mutable-файл при отсутствии mesh.
- Откат: не менять параллельность операций и не выполнять SSH в GUI-потоке.

### 5. Корректная статистика и updater

- Проблема: RMS абсолютных Z может смешивать смещение с неровностью; updater
  принимает любой `.exe` и неточно фильтрует суффикс тега.
- Место: `app.py`, `utils/updater.py`, соответствующие тесты.
- Реализация: явно разделить RMS абсолютных значений и RMS относительно среднего;
  выбирать точное имя EXE и только теги с окончанием `-win`.
- Проверка: статистика имеет однозначное назначение; тесты отбрасывают лишний
  EXE и похожие теги.
- Откат: сохранить SHA-256, sidecar checksum и текущий механизм перезапуска.

### 6. Сборка и runtime-проверка

- Runtime-уточнение после диагностической сборки: PyInstaller размещает Qt DLL
  в `PyQt6/Qt6/bin`, поэтому frozen entrypoint должен добавить этот каталог в
  DLL search path до импорта `PyQt6.QtWidgets`.
- Runtime-уточнение после onedir-диагностики: автоматически найденные
  `icuuc.dll`/`icudt78.dll` из окружения сборки конфликтуют с системным ICU,
  поэтому `pyi_rth_qt_dlls.py` удаляет только эти два файла из временного
  frozen-runtime до импорта Qt; проверка выполняется и для onedir, и для
  финального onefile.
- Место исправления: `win/pyqt6/main.py`,
  `win/pyqt6/pyi_rth_qt_dlls.py`.
- Собрать Windows onefile существующей командой из workflow на Python 3.10;
  не использовать старый `.spec`, если он расходится с workflow.
- Проверить наличие EXE и checksum; до запуска проверить исходные ресурсы
  `webpanel/gkbridge`, `webpanel/camera` и `win/pyqt6/ui/locale`, а после сборки
  проверить их попадание в PyInstaller bundle через `--debug=imports` или
  минимальный smoke-тест `resource_path` в собранном окружении.
- Запустить `dist/Bed.Mesh.Visualizer.exe` в отдельном процессе с таймаутом,
  убедиться, что процесс стартует без немедленного падения, затем завершить
  его штатно/через `Stop-Process` и проверить код/лог запуска.
- Зафиксировать только относящиеся к плану изменения task-only коммитом; push не
  выполнять без прямого запроса.

## Не входит в план

Изменения Android/macOS/webpanel, смена принятой модели локальных SSH-учётных
данных и изменение политики доверия host key.
